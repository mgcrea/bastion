# Bastion — Competitive Brief

**Research date:** 7 September 2026. Web sources as of that date; GitHub star counts and release dates are point-in-time and several release _years_ had to be inferred (flagged inline).
**Competitors covered:** Docker MCP Toolkit / Gateway / Catalog · ToolHive (Stacklok) · the OSS aggregator tier (MetaMCP, 1MCP, mcp-proxy ×2) with a short scan of adjacent tools, one of which (MCP Router) turned out to matter.
**Bastion context used:** README, `docs/`, and the website copy in `apps/website/src` — v1.0.0+, macOS menu-bar app, one supervised process per profile, Keychain credentials, per-profile write gate, hash-chained audit log, five loopback rules, OAuth/PKCE for remote servers, a built-in `bastion` control-plane server, no container runtime, no account, $14.99 / €14.99 once per major version, 30-minute in-memory trial, public source, sold as the signed build.

---

## 1. Executive summary

The local-MCP-gateway market has split into two camps in 2026 and Bastion sits in neither. The well-funded camp (Docker, Stacklok) has moved _up_: both now lead with "governance", "control plane", talk-to-sales enterprise SKUs and Kubernetes, and both still require a container runtime on a Mac. The OSS camp (MetaMCP, 1MCP, the two mcp-proxies) is single-maintainer, CLI- or compose-driven, and stores every credential as an environment variable, a JSON file or a Postgres row. Nobody in either camp is selling a native, one-price, no-Docker Mac app to the individual developer who runs Claude Code, Cursor and Claude Desktop side by side — and the demand signal for exactly that is visible in the competitors' own issue trackers (per-key permissions, audit layers, OrbStack support, "why does the gateway hang when Docker Desktop sleeps").

**Biggest opportunity:** own "credentials in the Keychain, never in a config file" and "every call recorded, tamper-evident" as _your_ sentences before anyone else says them at desktop scale. Every competitor either can't say the first (they store secrets in files) or says the second only behind a sales call.

**Biggest threat:** not Docker — it is the free tier of the category. MCP Router (2.1k stars, free, macOS+Windows, one-click wiring, request logs, per-tool toggles) and ToolHive Studio (free, Apache-2.0, "built by the team behind Kubernetes") are both zero-dollar desktop apps that a prospect will find first and that look 80% like Bastion in a screenshot. Bastion's defence has to be the 20% they cannot match without a rewrite: no container runtime, native Keychain, a write gate that removes tools from `tools/list`, and a chained audit file — plus the honesty of the pricing.

## 2. Competitor profiles

### 2.1 Docker MCP Toolkit / MCP Gateway / MCP Catalog

**Company overview.** Three linked products from Docker Inc.: the MCP _Catalog_ (a curated `mcp/` namespace on Docker Hub of signed container images, 300+ servers), the MCP _Toolkit_ (a Docker Desktop UI, Beta, to enable servers, manage OAuth and secrets, build "profiles" and one-click-wire clients), and the MCP _Gateway_ (the open-source Go CLI plugin, `docker mcp`, MIT, ~1.5k stars, latest release v0.43.x mid-2026). Catalog and Toolkit beta launched May 2025; Toolkit shipped in Docker Desktop 4.42 in June 2025; the OSS Gateway followed in July 2025. On 12 May 2026 Docker announced **Docker AI Governance** and an **MCP Enterprise Gateway** (sales-led, no public price, "managed in your cloud" or air-gapped appliance). The Gateway docs now carry the line: _"MCP Gateway as part of Docker AI Governance is an invite-only feature. Contact Docker Sales to learn more."_ — while the OSS binary stays downloadable. New CPO and CFO were hired in August 2026 "to support agentic workflow expansion".

**Messaging.** Catalog: _"Access the largest library of containerized MCP servers — built by the community, powered by Docker."_ Enterprise Gateway: _"One secure gateway for all your tools"_, _"Agents need access. Enterprises need control."_, _"Say what agents can do. Prove what they did."_, _"We already run the servers you are trying to govern."_ Governance: _"Defined once. Enforced everywhere."_ The 2025 problem framing is nearly identical to Bastion's opening paragraph: _"Many MCP tools run with full access to the host, launched via npx or uvx, with no isolation or sandboxing. Credentials are commonly passed as plaintext environment variables."_ Themes: supply-chain trust (signed images, SBOM), container isolation, secrets out of client configs, "configure once for every client", and in 2026 governance/audit ("laptops as the new prod", "YOLO mode with guardrails"). Tone: confident, security-first, increasingly CISO-facing.

**Product positioning.** Category labels: "MCP Gateway / Catalog / Toolkit", and since May 2026 "AI Governance" and "governed AI runtime". Emphasised: catalog breadth, per-container limits (1 CPU / 2 GB, no host filesystem by default), interceptors (`--log-calls`, `--block-secrets`, `--verify-signatures`), OAuth in the UI (extended to community servers in March 2026), profile templates, "Dynamic MCP" on-demand tool discovery, SIEM event streaming (enterprise only). Packaging: the Toolkit UI is bundled with Docker Desktop (works on the free Personal tier); Linux/headless runs the bare binary but loses the Desktop-only secrets plumbing (`docker-pass`, `se://` URIs), which community write-ups replace with a chmod-600 `.env`.

**Content strategy.** Heavy MCP how-to output in late 2025 ("6 must-have MCP servers", "MCP horror stories", a Claude Desktop guide), thinning in 2026 as the blog pivots to Sandboxes and governance (a CISO-bylined "Agentic AI needs guardrails, not guesswork", "Agent security is a systems problem", "YOLO Mode", "Below the harness" — four posts in the last six weeks). Video: the "AI Guide to the Galaxy" explainer series. Press: Forbes ran "Docker turns the developer laptop into a governed AI runtime" the day after the May launch. Organic buzz is low — the HN launch thread got four points.

**Strengths.** Brand and distribution: Docker Desktop is already on the Mac. The largest signed catalog. Real container isolation, which Bastion deliberately does not offer. A credible enterprise trust story and reference customers. Rapid release cadence on the OSS gateway.

**Weaknesses.** Requires Docker Desktop for the good parts, which is the single most repeated complaint: OrbStack users have had an open request since July 2025; the gateway "panics when Docker Desktop is unresponsive, killing the Claude session" (#312); Resource Saver mode hung secret fetches (acknowledged in release notes); Claude Code 30-second wiring timeouts (#336); "always starts in stdio mode — is this by design?" (#216); custom catalog servers invisible in the UI (#283). Enterprise pricing is undisclosed and the OSS gateway "leaves audit logging, tool-level RBAC and identity management to teams" (byteiota). Strategically, Docker is walking away from the individual developer toward the platform team — the invite-only line in the docs is the tell.

**Reverse-engineered positioning statement.** For platform and security teams governing AI agents across many clients, Docker MCP Toolkit/Gateway is the containerised MCP gateway and catalog that lets you approve, isolate and audit every tool call from one place, because Docker already is the runtime and already ships the signed servers.

### 2.2 ToolHive (Stacklok)

**Company overview.** Open-source (Apache-2.0) MCP platform from Stacklok, Seattle, founded 2023 by Craig McLuckie (Kubernetes co-creator) and Luke Hinds (sigstore founder); $17.5M Series A from Accel and Madrona, Bain Capital now also listed as an investor (no later round found — unverified). Pivoted from supply-chain security (Minder, CodeGate) to MCP in April 2025. Joe Beda (Kubernetes co-creator, Heptio) joined as CTO in April 2026. Core repo ~2.0k stars, 289 open issues, releases every two to four weeks (v0.28–v0.30, May–June 2026); ToolHive Studio (Electron desktop app for macOS, Windows, Linux) has 158 stars. Commercial layer: **Stacklok Enterprise MCP Platform**, "a hardened distribution" with Okta/Entra integrations, backported patches, hardened images, an enterprise cloud UI and SLA support, self-hosted, demo-only pricing. Hiring: forward-deployed Kubernetes engineers (Singapore, North America) — a services-heavy enterprise motion.

**Messaging.** Homepage: _"Run your new AI agents on your existing Kubernetes infrastructure."_ Platform page: _"The MCP platform that engineering leaders trust"_, _"Deployed in your private cloud, behind your firewall"_, _"You've been charged with leading your enterprise's MCP journey."_ Download page: _"The open source MCP platform trusted by developers and enterprises… built by the team behind Kubernetes and maintained by both Stacklok and Red Hat."_ GitHub/Studio: _"Run any Model Context Protocol (MCP) server — securely, instantly, anywhere."_ The 2025 launch post framed the problem as a developer would (_"Do I have to copy my API key into a clear text configuration file?"_); the 2026 site frames it for a VP ("shadow MCP deployments", "hardcoded credentials"). Themes: Kubernetes pedigree, container isolation with network egress filtering on by default, identity-first governance (OIDC + Cedar policy), OpenTelemetry/Prometheus observability, and "semantic tool search reduces token usage by 85%". Tone: authoritative platform-engineering.

**Product positioning.** Category: "MCP platform" / "Enterprise MCP Platform" / "AI control plane". Four components: Runtime (local Docker/Podman or K8s operator), Registry (curated, claims-based access), Gateway (vMCP aggregation, MCP Optimizer, rate limiting, Redis session routing), Portal (desktop + web UI, Playground, agent skills). Secrets: "a built-in encrypted store that uses your operating system's keyring to protect a local secrets file", 1Password, or HashiCorp Vault — note the wording: the keyring protects a _file_, the secrets are not individual Keychain items. Client auto-config for VS Code/Copilot, Cursor, Claude Code, Copilot CLI. Prerequisite on a Mac is explicit: _"Docker / Docker Desktop, Podman / Podman Desktop, Colima with the Docker runtime"_; npm and PyPI servers are auto-containerised. Free; enterprise is talk-to-sales.

**Content strategy.** Several blog posts a month, often batched, moving from how-to toward category-defining thought leadership: "What is an agent harness?", "How to choose an agent harness", "Observer or governor? Why your AI control plane needs identity-first controls", "The two-door problem: MCP gateway and LLM gateway", "Is your AI control plane Kubernetes-native or Kubernetes-compatible?", "What good AI spend governance looks like". A weekly "ToolHive Updates" changelog in the docs since December 2025. Discord, YouTube, a Meetup user group, dev.to cross-posts. Press: Help Net Security profile (7 Sep 2026), The New Stack, a Red Hat Developer OpenShift tutorial (Oct 2025 — the "maintained by Red Hat" claim is Stacklok's own and was not independently confirmed).

**Strengths.** Credibility (Kubernetes founders, Red Hat association, Apache-2.0). Genuinely broad: local runtime through K8s operator through enterprise. Network egress filtering and OTel are ahead of Bastion. Free desktop app with client auto-wiring. Very active engineering and a disciplined changelog.

**Weaknesses.** The Mac experience is a container runtime plus an Electron shell — "substantially more platform than a single-user setup needs" (zimaspace's 2026 gateway roundup). Studio issues skew to cross-platform polish (Mac-native theme override, Linux updater misbehaving, port changes on edit). 289 open issues on the core repo. A June 2026 path-traversal advisory (GHSA-hfrv-94x5-85p2). The individual developer is not the buyer any more; the website says "engineering leaders" and "private cloud". No per-profile write gating in the Bastion sense (authorization is Cedar policy at the platform tier, not a desktop switch).

**Reverse-engineered positioning statement.** For platform-engineering and security leaders adopting AI agents, ToolHive is the open-source, Kubernetes-native MCP platform that runs any server in isolated containers with identity-based governance and audit, because it was built by the team behind Kubernetes and reuses the cloud-native controls you already trust.

### 2.3 The OSS aggregator tier

**MetaMCP** (metatool-ai, MIT, ~2.6k stars). Tagline: _"MCP Aggregator, Orchestrator, Middleware, Gateway in one docker"_; hero: _"The One MCP to manage all your MCPs."_ Docker-compose deployment with Postgres, 2–4 GB instance minimum, three-tier Servers → Namespaces → Endpoints model, API keys and OIDC SSO, MCP OAuth on endpoints, Inspector. Secrets are `${VAR}` interpolation into config stored in Postgres. Auth is all-or-nothing — _"there is no granular RBAC in MetaMCP"_ — and tool-call logging was still on the roadmap in August 2026 (per a "Why I replaced MetaMCP with a custom gateway" post). Last tagged release appears to be v2.4.22 in December 2025 (year inferred); no tagged release found March–September 2026 while issues keep arriving (session-pool saturation returning empty tool lists, sub-server crashes taking the app down, restart rituals, a "security scan grade C" issue). Effectively single-maintainer. Positioning: for teams wanting a self-hosted multi-user MCP control plane, the compose-stack gateway that bundles aggregation, UI, auth and middleware.

**1MCP** (William Xu, Apache-2.0, ~455 stars). Hero: _"One runtime for MCP, one thinner workflow for agents"_; npm: _"One MCP server to aggregate them all."_ Node/npm, CLI-only, no GUI. The closest architectural sibling to Bastion: a single `1mcp serve` process explicitly shared by all clients, `1mcp app consolidate` that rewrites Claude Desktop/Cursor/VS Code/Claude Code/Gemini/Cline configs to point at it (with backups), tags and presets for per-client tool subsets, OAuth 2.1 for incoming clients, an OAuth dashboard for remote servers with refresh rotation, an Admin Console (v0.35, Aug 2026). Secrets: `mcp.json` plus `.env`; v0.37 (31 Aug 2026) hardened token files to 0600 — still files, no keychain. Logs, not per-call audit. Ships weekly; an "[MCP 2026]" epic batch on 23 Aug signals a refactor for the 2026-07-28 spec. Only 20 open issues, mostly the maintainer's own roadmap; almost no external chatter. Positioning: for developers running several agent CLIs on one machine, the single-process runtime that consolidates every client's config.

**mcp-proxy (sparfenyuk, Python, MIT, ~2.7k stars)** — _"A bridge between Streamable HTTP and stdio MCP transports."_ A transport bridge, not a manager: bearer token via env var, client-credentials OAuth since v0.11/0.12 (May 2026), no UI, no filtering, no per-client config. Quarterly releases. Its issue tracker is a wish-list for what Bastion already does: a single server failure crashes the whole proxy (#198), per-API-key permissions per server (#201), circuit breaker (#202), and — June 2026 — _a tamper-evident audit layer_ (#224).

**mcp-proxy (TBXark, Go, MIT, ~718 stars)** — _"An MCP proxy that aggregates multiple MCP servers behind a single HTTP entrypoint."_ Single binary, JSON config with `authTokens`, per-client `toolFilter` allow/block lists, downstream OAuth held once for all callers (v0.58, Aug 2026), health endpoints. Secrets in plaintext JSON/env. Rapid releases, thin community.

**Adjacent tools worth one line each.** _MCP Router_ (2.1k stars, "Sustainable Use License", free, macOS + Windows Electron desktop app): one-click wiring for Claude/Cline/Windsurf/Cursor, per-tool toggles, request logs and analytics, credentials "stored locally and never transmitted externally" — **the closest direct look-alike to Bastion** and the one to watch; no Keychain claim, no write gate, non-OSI licence. _MCPJungle_ (1.2k, Go, per-client ACLs in "enterprise mode"). _IBM ContextForge_ (4.3k, Apache-2.0, federating registry/proxy with OTel — enterprise K8s). _Microsoft MCP Gateway_ (K8s reverse proxy). _Obot_ (full platform; its Nanobot proxy is in maintenance mode). _Lasso mcp-gateway_ (guardrails: PII masking, prompt-injection detection). _mcp-hub_ (Neovim-ecosystem manager with REST API). Hosted: _Rube_ (Composio, "500+ apps"), _Glama_ gateway (~4,000 hosted connectors). All of these are either server-side or cloud; none is a native Mac app.

### Narrative analysis (villain / hero / transformation / stakes)

Docker's villain is the ungoverned agent on a developer laptop; the hero is the platform team; the transformation is "YOLO mode with guardrails"; the stakes are a compliance incident. ToolHive's villain is shadow MCP and hardcoded credentials; the hero is the engineering leader "charged with leading your enterprise's MCP journey"; the stakes are losing control of the rollout. MetaMCP and 1MCP have no villain beyond sprawl — the story is tidiness. Bastion's villain is concrete and personal: _a brokerage refresh token sitting in a file beside the code, one careless `git add` from being published_, plus 5.7 GiB of duplicate processes. The hero is the developer themself, and the transformation is auditable trust in a background daemon. That is the sharpest and most checkable story in the category; it is also the only one whose evidence section links to _other people's_ bug trackers.

### Clarity, differentiation, proof, consistency

Bastion scores highest on proof (every claim points at a `make` target or a linked issue) and lowest on five-second clarity: "supervises your MCP servers instead of letting each editor spawn its own" assumes the reader already knows what a stdio server is. Docker and ToolHive are clearer to a manager and vaguer to a developer. The aggregators are clear to developers and prove nothing.

## 5. Opportunities

**The "no Docker" sentence is undefended.** Both incumbents require a container runtime on macOS and both have public issues about what happens when that runtime sleeps, restarts or isn't Docker (OrbStack). "No container runtime, no Docker Desktop, no sign-up" is already on Bastion's pricing card; promote it to the hero.

**Keychain is unclaimed at the item level.** Docker's secrets are Desktop-only, ToolHive's keyring protects a single encrypted file, and every aggregator uses env vars or JSON. "Each credential is its own Keychain item, per profile, and no tool can return one" is a sentence no competitor can currently write.

**The write gate as a model-facing feature.** Everyone else filters or refuses; Bastion removes gated tools from `tools/list` so a model never plans around a tool it cannot use. That is a positioning angle about _agent reliability_, not just safety, and nobody is making it.

**Audit that admits its limits.** Docker sells "prove what they did" behind a sales call; ToolHive points at OTel. Bastion's hash-chained JSONL with an explicit "what it does not prove" page is more credible to exactly the sceptical developer audience it wants, and mcp-proxy users are literally filing issues asking for it.

**The abandoned individual.** Docker's docs say invite-only; Stacklok's homepage says "engineering leaders"; MetaMCP has stalled. The solo developer with three IDEs and thirty servers is being handed off to free Electron apps. A paid, native, one-time-purchase Mac utility with a 30-minute whole-app trial is a familiar and trusted shape to that buyer.

**Comparison pages.** Third-party roundups (zimaspace, heyitworks, mcp.directory) are currently defining the category and don't list Bastion. A factual "Bastion vs Docker MCP Toolkit / vs ToolHive Studio / vs MCP Router" page in Bastion's own voice — with the gaps column included, as the site already does for itself — would capture high-intent search and get cited.

## 6. Threats

**Free look-alikes.** MCP Router and ToolHive Studio are free, cross-platform, and screenshot-similar. A prospect comparing feature bullets sees "one-click wiring, logs, tool toggles" on both sides and a price on only one. Bastion must make the differences visible in the first screen, not the README.

**Docker's distribution.** If Docker ever ships a lightweight, no-container "profile" mode in Desktop or turns the Toolkit UI loose from Desktop, the "no Docker" advantage narrows. Its cadence (v0.42→v0.43 in six weeks, npm servers now in the catalog) shows it is closing the "we only run containers" gap.

**Spec churn.** The 2026-07-28 stateless-first spec is what makes Bastion's one-handshake design correct; 1MCP has already opened an "[MCP 2026]" refactor epic. Any future spec move back toward per-client state (list_changed, subscriptions, elicitation — all in Bastion's own gaps list) favours one-process-per-client designs.

**Platform lock.** macOS only is a clean story but excludes every Linux/WSL developer that Docker's and ToolHive's issue trackers show asking for help. Not a near-term threat to positioning, but it caps the addressable market the roundups measure against.

**Governance narrative capture.** If "audit" becomes synonymous with SIEM/OTel/enterprise in buyers' minds, Bastion's in-app audit reads as a toy rather than a design. Keep the audit story technical (chain, manifest, 0600, what it can't prove) rather than adopting governance vocabulary.

## 7. Recommended actions

**Quick wins (this week)**

1. Move "No container runtime. No Docker Desktop. No account." from the pricing card into or directly under the hero. It is the single most-searched pain in both incumbents' trackers and Bastion already has the line written.
2. Add one sentence about the Keychain that the competitors cannot copy: "Each credential is its own Keychain item, per profile — no tool can return one, and the audit log blanks it." Ship it on the hero or Problem section.
3. Publish the changelog on bastion.mgcrea.io (or link CHANGELOG.md visibly). ToolHive's weekly updates page is doing quiet SEO work; Bastion's is already written.
4. Get Bastion into the roundups that define the category: open PRs or emails to the heyitworks Q1-2026 survey, mcp.directory, zimaspace's "top 10 MCP gateways", and awesomeclaude.ai's aggregator list. They currently list MCP Router and not Bastion.

**Strategic moves (next quarter)**

5. Write the three comparison pages — vs Docker MCP Toolkit, vs ToolHive Studio, vs MCP Router — in the site's existing "what we check vs what others assert" voice, with a gaps column for Bastion too. These are the highest-intent pages a small vendor can own.
6. Turn the "Problem" evidence into the definitive measured post: "What three MCP clients actually cost your Mac" — reproduce the 3.5 GB / 5.7 GiB / 82-children figures on your own machine, before and after Bastion, with the script. It is the one topic no competitor has measured in public and it links back to their own trackers.
7. Record a 90-second menu-bar demo (install from catalog → profile → wire Claude Code and Cursor → watch the audit line). Both incumbents have video; the aggregators don't; a native app demos better than a compose stack.
8. Close the "login item" gap before the comparison pages go live — it is the one row where a free Electron app currently beats Bastion in a feature table, and it is already listed on the site as a known gap.
9. Decide the Linux question explicitly in public (a FAQ line: "macOS only, by design, because of the Keychain and the signed build") so roundups stop marking it as a missing feature and start marking it as a choice.
